# FinDetect — геймификация
Описание фичи и use cases. Актуализация: 10.11.2026.

Общие правила — 01, базовые сценарии — 02, прогноз — 03.
Это целевое поведение по актуальным макетам, а не список уже готовых модулей.

## 1. Цель и принципы

Помочь регулярно вносить доходы и расходы вручную. Награждается привычка вести учёт, а не минимальные расходы любой ценой.

Детективная тематика: улики, следователь, достижения. Тон спокойный: пропуск не должен сопровождаться обвинением или потерей заработанных XP. Уровни косметические и не закрывают финансовые функции.

Игровое представление отключается в настройках. Базовый учёт, прогноз и возможность подтвердить день без трат сохраняются.

## 2. Активный день

- Активность: создана хотя бы одна операция или нажата «Сегодня трат не было».
- Учитывается день первоначального ввода по часовому поясу устройства. Дата самой покупки может быть другой.
- Внесение сегодня нескольких старых операций создаёт один активный день.
- Редактирование, удаление, повторная синхронизация и корректировка баланса не являются новой операцией для XP.
- Отметка дня без трат доступна за сегодня, один раз. Если уже внесён расход с сегодняшней датой, подтверждать отсутствие трат нельзя; наличие одного дохода такой отметке не мешает.
- Отметка не запрещает последующий ввод расходов. Если позже появилась трата, день остаётся активным, а для прогноза используется реальная сумма расходов.
- Удаление введённой операции не отнимает уже начисленные XP и не удаляет исторический факт активности.

Активность хранится с локальной датой и моментом ввода. Синхронизация офлайн-истории может прийти намного позже: сервер не должен отбрасывать старые корректные дни только из-за даты отправки. Проверки невозможных будущих дат не заменяют поддержку офлайна.

Для прогноза дата ввода и дата расхода имеют разное значение, см. 03.

## 3. Серия и день запаса

### 3.1 Правило

Серия считает активные дни. Один завершившийся пропущенный день можно простить:
- активный день увеличивает серию на 1;
- первый пропуск при доступном запасе расходует запас, но не увеличивает и не сбрасывает серию;
- следующий пропуск без восстановленного запаса сбрасывает серию;
- запас восстанавливается после 7 активных дней подряд после его использования;
- после сброса новая серия начинается с доступным запасом;
- сегодняшний незавершившийся день ещё не считается пропуском.

Рекорд — максимальная серия за историю, не уменьшается после сброса.

Пример: 5 активных дней → пропуск → 3 активных дня → пропуск: серия сброшена.
Если между пропусками 7 активных дней, запас успевает восстановиться.

### 3.2 Расчёт

Состояние пересчитывается по отсортированным активным датам. Клиент делает это локально, сервер — по объединённой синхронизированной истории с параметром `today`. Пропущенные дни не превращаются в активные.

При слиянии двух устройств одинаковая дата не должна увеличивать серию дважды. Объединяются признаки активности, а не готовые числовые серии.

### 3.3 Отображение

На главном: плашка серии, 7 дней текущей недели с отметками, «Рекорд: N дней». Отмечаются реальные активные дни, а не всегда семь галочек из демонстрационного макета.

Нажатие открывает «Серия дней»:
1. Крупный блок серии и неделя.
2. Рекорд.
3. Титул, уровень и XP.
4. «Каждый день имеет значение».
5. «Сегодня трат не было».
6. Строка «Рекорд» с лучшим значением.

Статус дня запаса не показывается постоянно. После его использования допустимо сообщение «Серия сохранена. Ещё один пропуск до восстановления запаса начнёт её заново». При сбросе — спокойное предложение начать новую.

В шапках расходов/доходов индикатора серии больше нет. Профиль не является экраном-хабом серии.

## 4. XP и уровни

Сохраняются прежние правила начисления:
- новая операция: +10 XP, не более 5 засчитанных операций за локальный день;
- отметка дня без трат: +5 XP, не более одной за день;
- вехи серии 3, 7, 14, 30, 100 дней — бонус;
- достижение — бонус 20–100 XP.

Конкретные суммы бонусов вех/достижений и пороги уровней в исходной спецификации не зафиксированы. Их нужно задать единой конфигурацией клиента/сервера. Значения «Уровень 2» и «140 / 250 XP» на макете — пример отображения, не новая таблица порогов.

Титулы:
1. Стажёр.
2. Следователь.
3. Старший следователь.
4. Детектив.
5. Главный детектив.

Для полосы прогресса используются `totalXp`, `levelStartXp`, `nextLevelXp`: текущий прогресс = totalXp − levelStartXp, длина уровня = nextLevelXp − levelStartXp. На максимальном уровне следующего порога нет, показывается достигнутый уровень без деления на ноль.

Начисления — журнал событий с устойчивыми UUID. Повтор отправки использует тот же UUID. Одна и та же веха/достижение не засчитывается повторно даже при разных событиях с двух устройств. Ограничения дней применяет также сервер.

Отметка и последующие операции в тот же день начисляются по собственным лимитам. XP не отнимаются при последующей правке или удалении записи.

## 5. Достижения: 11 кодов

Сохранён набор из прежней спецификации и API. Он не заменяется произвольными названиями из моковых данных.

| Код API | Название | Условие |
|---|---|---|
| FIRST_CLUE | Первая улика | Первая созданная операция |
| STREAK_3 | Три дня в деле | Серия 3 дня |
| STREAK_7 | Неделя в деле | Серия 7 дней |
| STREAK_14 | Две недели в деле | Серия 14 дней |
| STREAK_30 | Месяц в деле | Серия 30 дней |
| STREAK_100 | Сто дней в деле | Серия 100 дней |
| BACK_IN_ACTION | Снова в строю | После сброса 3 активных дня подряд |
| FRESH_CLUES | Свежие улики | 7 дней подряд операции внесены в день совершения |
| WITHIN_LIMIT | В рамках дела | Неделя в пределах ориентира расходов |
| REACHED_INCOME | Дотянул до поступления | Достигнута дата дохода без ухода в минус |
| FORECASTER | Прогнозист | Задана дата следующего дохода |

Для FRESH_CLUES дни без операций не должны давать награду автоматически; точный учёт подтверждённых нулевых дней нужно включить в согласованные примеры проверки.

WITHIN_LIMIT и REACHED_INCOME требуют данных прогноза. Для WITHIN_LIMIT нельзя задним числом оценивать неделю по только что пересчитанному дневному ориентиру: нужны сохранённые значения или заранее зафиксированное правило. Эти два условия остаются задачей согласования до автоматической выдачи, их API-коды сохранены.

В макете есть закрытая строка «Финансовый след» без описанного условия. Её соответствие одному из перечисленных кодов не определено. Нельзя добавлять двенадцатое достижение или молча заменять условие существующего. Требуется согласовать название и код с командой.

Экран «Достижения» показывает «Открыто N из 11», открытые и закрытые элементы. Открытый — тематическая SVG-иконка и условие; закрытый — замок и короткое условие/прогресс. «Ещё 6 достижений» — сокращение демонстрационного списка; все 11 должны быть доступны при прокрутке, отдельная кнопка перехода этой строки не задана.

На главном — превью и счётчик. Получение достижения может сопровождаться коротким сообщением; отдельный праздничный экран дизайном не предусмотрен. Награды: иконка, XP, титул, без финансовых призов.

## 6. Напоминания

Настройки → «Напоминания»:
- «Напоминать об учёте»;
- время, на макете 20:00;
- «Периодичность» — «Ежедневно»;
- пояснение о разрешении;
- «Открыть настройки» для системных настроек уведомлений.

Другие режимы периодичности в дизайне не раскрыты. Настройки применяются сразу, без отдельной кнопки сохранения.

Напоминание локальное и не требует интернета. Планировщик и разрешения нужно реализовать/проверить, наличие WorkManager в старом проекте не доказывает готовность в этом.

Правила:
- если за сегодня есть активность, обычное напоминание не показывается;
- если активности нет, предложить внести операции либо подтвердить отсутствие трат;
- при серии от 3 дней текст может предупреждать о риске пропуска;
- общее ограничение — не более одного уведомления FinDetect за день, с учётом уведомления прогноза;
- отдельный повтор в 21:00 не отправляется, если уведомление уже было показано в выбранное время;
- учитывать локальное время, тихие часы и отказ в разрешении, не обещать точный запуск фонового планировщика.

Запрашивать разрешение после понятного действия пользователя, например включения напоминаний, с объяснением. При отказе основной учёт работает, карточка настроек ведёт к системным разрешениям. Нажатие уведомления открывает главный экран после PIN при необходимости.

## 7. Данные и синхронизация

| Сущность | Слияние |
|---|---|
| ActivityDay | Ключ — локальная дата; признаки операции/отметки объединяются, первый момент ввода сохраняется |
| XpEvent | Ключ UUID, повтор идемпотентен; сервер применяет лимиты и возвращает `counted`/`amount` |
| Achievement | Ключ — код; сохраняется самая ранняя дата получения |
| Progress | Итог сервера: серия, рекорд, запас, XP, уровень, пороги и достижения |

Клиент обновляет представление сразу, не ожидая сети. После синхронизации принимает итог, пересчитанный сервером. Финансовые записи отправляются раньше связанной активности/прогресса. Подробный порядок — в 01/API.

Нельзя синхронизировать только число XP и складывать два готовых итога: это создаёт дубли. Локальный журнал сохраняет события до подтверждения.

## 8. Расположение и отключение

| Место | Что показано |
|---|---|
| Главный | Краткий профиль с уровнем/XP, серия недели и рекорд, превью достижения |
| Серия дней | Полная серия, рекорд, уровень/XP, отметка отсутствия трат |
| Достижения | Набор из 11 и прогресс открытия |
| Профиль | Аккаунт и строка уровня, без карточек серии/прогноза |
| Настройки | «Игровые элементы» и отдельные «Напоминания» |

При выключении игровых элементов скрываются серия, титулы, XP и достижения в основном представлении. Данные не удаляются. Обычный профиль и финансовые блоки остаются.

Отметка дня без трат нужна прогнозу независимо от игры. После скрытия серии нужен доступный неигровой способ поставить её; конкретный маршрут не показан в новых макетах и требует дополнения. Не оставлять единственную кнопку на скрытом экране.

Общие напоминания об учёте регулируются собственным переключателем; сообщения о серии при выключенной игре не используются. Отдельного экрана управления игровыми элементами пока нет в приложенном дизайне.

## 9. Точки реализации и приоритеты

Событие успешного локального создания операции обновляет активность и журнал XP атомарно или с гарантией повторного завершения без дублей. Не связывать начисление с нажатием кнопки или успешным HTTP-ответом: офлайн тоже должен работать.

Хранение активности/XP, миграции, синхронизация и планировщик — целевые задачи. Не считать их уже перенесёнными из старого приложения.

P0: реальные активные даты, серия/запас, рекорд, отметка без трат, главный и отдельный экран серии.
P1: XP/уровни, список достижений, настройка отображения и напоминания.
Перед выдачей всех наград: согласовать бонусы/пороги, условия зависимых от прогноза достижений и «Финансовый след».

## Use cases

### UC-24. «Сегодня трат не было»

1. Открыть «Серия дней» с главного.
2. Если сегодня ещё нет отметки и нет сегодняшнего расхода, нажать кнопку.
3. Сохранить отметку локально, обновить серию, начислить +5 XP с дневным ограничением.
4. Показать состояние «Отмечено» до следующих суток.

Позднейшие расходы разрешены и участвуют в прогнозе, серия не теряется. Подтверждение задним числом недоступно. При выключенной игре нужен отдельный доступ к действию (см. раздел 8). Онлайн/офлайн одинаково.

### UC-25. Серия и прогресс

1. На главном показать реальную неделю, число дней и рекорд.
2. Нажать блок → «Серия дней».
3. Показать рекорд, титул, уровень и прогресс XP.
4. Сообщение о запасе появляется при его использовании/восстановлении, а не постоянно.
5. После сброса предложить начать новую без потери XP.

Состояние доступно локально; после синхронизации принимается согласованный итог.

### UC-28. Достижения

1. Нажать блок достижений на главном.
2. Показать счётчик и все доступные 11 элементов.
3. Полученные отображаются тематическими иконками, закрытые — замками с условиями.
4. Новая выдача создаёт устойчивую запись достижения и событие XP. Повторная синхронизация не выдаёт награду снова.

Офлайн доступны локальные условия. Достижения, требующие достоверного прогноза, не выдаются на основании моковых значений.

### UC-29. Напоминания

1. Настройки → «Напоминания».
2. Включить, выбрать время, оставить поддерживаемую ежедневную периодичность.
3. При необходимости запросить системное разрешение; при отказе показать пояснение и «Открыть настройки».
4. В подходящее время без активности показать одно напоминание с учётом дневного ограничения.
5. Нажатие открывает главный; PIN проверяется, если включён.

Интернет не нужен. При выключении напоминаний запланированные уведомления отменяются.

## 10. Отложенные возможности

### Расследование недели — UC-27

Короткий отчёт за прошлую неделю: самая затратная категория/день/покупка, мелкие повторяющиеся траты и сравнение с предыдущей неделей. Возможный мини-вызов и награда. Для текущего объёма не включены:
- блок расследования;
- сущность Investigation;
- награды/XP за расследование;
- уведомления об итогах и дополнительные достижения.

При возвращении фичи отдельно обновить дизайн, контракт и число достижений.

### Виджет

Варианты на будущее: серия либо быстрое добавление операции. Возможная реализация через Glance читает локальные данные; быстрый ввод проходит через PIN при включённой блокировке. В текущие макеты и API не включён.
