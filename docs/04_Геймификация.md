# FinDetect — геймификация
Описание фичи и use cases. Актуализация: 17.11.2026.

Общие правила — 01, базовые сценарии — 02, прогноз — 03.
Это целевое поведение по актуальным макетам, а не список уже готовых модулей.

## 1. Цель и принципы

Помочь регулярно вносить доходы и расходы вручную. Награждается привычка вести учёт, а не минимальные расходы любой ценой.

Детективная тематика: улики, следователь, достижения. Тон спокойный: пропуск не должен сопровождаться обвинением или потерей заработанных XP. Уровни косметические и не закрывают финансовые функции.

Игровое представление отключается в настройках. Базовый учёт, прогноз и возможность подтвердить день без трат сохраняются.

## 2. Активный день

- Активность: создана хотя бы одна операция или нажата «Сегодня трат не было».
- Учитывается день первоначального ввода по часовому поясу устройства. Дата самой покупки может быть другой.
- Внесение сегодня нескольких старых операций создаёт один активный день.
- Редактирование, удаление, повторная синхронизация и корректировка баланса не являются новой операцией для XP.
- Отметка дня без трат доступна за сегодня, один раз. Если уже внесён расход с сегодняшней датой, подтверждать отсутствие трат нельзя; наличие одного дохода такой отметке не мешает.
- Отметка не запрещает последующий ввод расходов. Если позже появилась трата, день остаётся активным, а для прогноза используется реальная сумма расходов.
- Удаление введённой операции не отнимает уже начисленные XP и не удаляет исторический факт активности.

Активность хранится с локальной датой и моментом ввода. Синхронизация офлайн-истории может прийти намного позже: сервер не должен отбрасывать старые корректные дни только из-за даты отправки. Проверки невозможных будущих дат не заменяют поддержку офлайна.

Для прогноза дата ввода и дата расхода имеют разное значение, см. 03.

## 3. Серия и день запаса

### 3.1 Правило

Серия считает активные дни. Один завершившийся пропущенный день можно простить:
- активный день увеличивает серию на 1;
- первый пропуск при доступном запасе расходует запас, но не увеличивает и не сбрасывает серию;
- следующий пропуск без восстановленного запаса сбрасывает серию;
- запас восстанавливается после 7 активных дней подряд после его использования;
- после сброса новая серия начинается с доступным запасом;
- сегодняшний незавершившийся день ещё не считается пропуском.

Рекорд — максимальная серия за историю, не уменьшается после сброса.

Пример: 5 активных дней → пропуск → 3 активных дня → пропуск: серия сброшена.
Если между пропусками 7 активных дней, запас успевает восстановиться.

### 3.2 Расчёт

Состояние пересчитывается по отсортированным активным датам. Клиент делает это локально, сервер — по объединённой синхронизированной истории с параметром `today`. Пропущенные дни не превращаются в активные.

При слиянии двух устройств одинаковая дата не должна увеличивать серию дважды. Объединяются признаки активности, а не готовые числовые серии.

### 3.3 Отображение

На главном: плашка серии, 7 дней текущей недели с отметками, «Рекорд: N дней». Отмечаются реальные активные дни, а не всегда семь галочек из демонстрационного макета.

Нажатие открывает «Серия дней»:
1. Крупный блок серии и неделя.
2. Рекорд.
3. Титул, уровень и XP.
4. «Каждый день имеет значение».
5. «Сегодня трат не было».
6. Строка «Рекорд» с лучшим значением.

Статус дня запаса не показывается постоянно. После его использования допустимо сообщение «Серия сохранена. Ещё один пропуск до восстановления запаса начнёт её заново». При сбросе — спокойное предложение начать новую.

В шапках расходов/доходов индикатора серии больше нет. Профиль не является экраном-хабом серии.

## 4. XP и уровни

Правила этого раздела согласованы с пользователем 17.11.2026. Это требования к реализации, а не подтверждение готовности кода. Пороги, суммы наград и ограничения задаются единой конфигурацией клиента/сервера; значения из демонстрационных макетов её не заменяют.

### 4.1. Уровни и титулы

| Уровень | Титул | Порог общего опыта |
|---|---|---:|
| 1 | Стажёр | 0 XP |
| 2 | Следователь | 250 XP |
| 3 | Старший следователь | 1 000 XP |
| 4 | Детектив | 2 500 XP |
| 5 | Главный детектив | 5 000 XP |

- `totalXp` — опыт, накопленный за всё время. При повышении уровня он не обнуляется.
- Уровень определяется по наибольшему достигнутому порогу. Если одно начисление пересекло несколько порогов, сразу показывается соответствующий итоговый уровень.
- `levelStartXp` — порог текущего уровня, `nextLevelXp` — порог следующего.
- Текущий прогресс полосы: `totalXp - levelStartXp`; длина уровня: `nextLevelXp - levelStartXp`; до следующего уровня: `nextLevelXp - totalXp`.
- Пример: при 700 XP пользователь имеет уровень 2, титул «Следователь», прогресс 450 из 750 XP; до уровня 3 осталось 300 XP.
- На уровне 5 опыт продолжает накапливаться. Следующего порога нет: `nextLevelXp` и `xpToNextLevel` равны `null`, показывается «Максимальный уровень» без деления на ноль.
- Уровни косметические и не ограничивают доступ к финансовым функциям.

### 4.2. Начисления и ограничения

| Основание | Награда | Ограничение |
|---|---:|---|
| Создание расхода или дохода | +10 XP | Первые 5 успешно созданных операций за локальный день |
| «Сегодня трат не было» | +5 XP | Одна успешная отметка за локальный день |
| Серия 3 активных дня | +20 XP | Один раз на аккаунт |
| Серия 7 активных дней | +50 XP | Один раз на аккаунт |
| Серия 14 активных дней | +100 XP | Один раз на аккаунт |
| Серия 30 активных дней | +200 XP | Один раз на аккаунт |
| Серия 100 активных дней | +500 XP | Один раз на аккаунт |

- День операции определяется по первоначальному вводу и часовому поясу устройства, а не по дате покупки. Операции за прошлые даты, впервые внесённые сегодня после подключения XP, используют сегодняшний лимит. Сохранённая локальная дата начисления не меняется при последующей смене часового пояса.
- Лимит пяти операций общий для всех счетов, валют, расходов и доходов пользователя. Размер суммы не влияет на XP. Шестая и последующие операции в этот день не дают дополнительного опыта.
- Отметка без трат доступна по правилам раздела 2: наличие дохода не мешает, наличие неудалённого расхода с сегодняшней датой не позволяет подтвердить отсутствие трат. Повтор отметки не начисляет XP.
- Лимиты операций и отметки независимы. Последующий расход разрешён и не отменяет ранее полученные +5 XP. Без бонусов можно получить до 55 XP в день; бонусы вех и будущих достижений в этот предел не входят.
- Редактирование, удаление, отмена удаления, корректировка баланса и повторная синхронизация не создают новое начисление. Удаление операции не отнимает XP и не освобождает использованное место в дневном лимите.
- Вехи определяются по правилам серии из раздела 3. День запаса сохраняет серию, но не увеличивает число активных дней и сам не приносит XP.
- Каждая веха оплачивается один раз за всё время аккаунта. Повторный набор такой же серии после сброса не даёт её бонус снова. Пропуск и сброс серии не отнимают накопленный опыт.
- Награды за достижения составляют 20–100 XP; конкретные суммы, условия и суммирование с бонусами вех согласованы в разделе 5. Автоматическая выдача достижений реализуется отдельным этапом после XP/уровней.

### 4.3. Начало начислений и существующая история

- Начисление XP начинается с момента подключения этой функции для пользователя. Момент начала фиксируется и сохраняется; перезапуск приложения не начинает отсчёт заново.
- Старые операции и отметки не получают XP задним числом. Существующая серия, рекорд и история активности сохраняются.
- Вехи серии, уже достигнутые до подключения XP, фиксируются как ранее пройденные без выплаты задним числом. Для этого учитывается вся прежняя история, а не только текущая серия.
- После подключения XP оплачиваются впервые достигнутые новые вехи. Например, если до подключения был достигнут максимум 7 дней, вехи 3 и 7 не оплачиваются; первое последующее достижение 14 дней даёт +100 XP.
- Новый пользователь начинает с 0 XP, уровня 1 и титула «Стажёр».

### 4.4. Сохранность и отображение

- Начисления хранятся в журнале событий с устойчивыми UUID, отдельно для каждого пользователя. Повтор отправки использует тот же UUID.
- Повтор обработки одной операции или отметки не создаёт новую награду. Одна и та же веха/достижение не засчитывается повторно даже при разных событиях с двух устройств. Ограничения дней применяет также сервер.
- Успешное создание операции или отметки сохраняет финансовые данные/активность и соответствующее начисление атомарно либо с гарантией повторного завершения без дублей. Начисление не зависит от открытия экрана и доступности сети.
- Главный экран, профиль и экран «Серия дней» используют общий источник прогресса, без отдельных расчётов порогов или макетных значений в каждом экране.
- При выключении игровых элементов начисление и сохранение прогресса продолжаются. После включения отображается актуальный накопленный результат.

Пункт 6 — ручная проверка на устройстве — ожидает сборки в Android Studio. Согласованные правила XP/уровней находятся в разделе 4.

### 5.1. Каталог и награды

Сохраняются 11 кодов из спецификации и API. Названия и условия не заменяются моковыми данными. Награда в таблице — XP именно за достижение, отдельно от базовых начислений и бонусов вех серии.

| Код API | Название | Условие | Награда |
|---|---|---|---:|
| FIRST_CLUE | Первая улика | Первая успешно созданная операция: расход или доход | 20 XP |
| STREAK_3 | Три дня в деле | Серия 3 активных дня | 20 XP |
| STREAK_7 | Неделя в деле | Серия 7 активных дней | 30 XP |
| STREAK_14 | Две недели в деле | Серия 14 активных дней | 50 XP |
| STREAK_30 | Месяц в деле | Серия 30 активных дней | 70 XP |
| STREAK_100 | Сто дней в деле | Серия 100 активных дней | 100 XP |
| BACK_IN_ACTION | Снова в строю | После реального сброса серии набраны 3 календарных дня активности подряд | 30 XP |
| FRESH_CLUES | Свежие улики | 7 завершённых календарных дней подряд во всех операциях дата первоначального ввода совпадает с датой совершения; каждый день содержит хотя бы одну операцию | 50 XP |
| WITHIN_LIMIT | В рамках дела | 7 завершённых дней подряд известны расходы и заранее сохранённые дневные ориентиры; каждый день расходы не превышают его ориентир | 70 XP |
| REACHED_INCOME | Дотянул до поступления | Завершён заранее заданный период до даты дохода, доступный остаток ни разу не становился отрицательным | 100 XP |
| FORECASTER | Прогнозист | Успешно сохранена корректная будущая дата следующего дохода | 20 XP |

Подключены все 11 достижений. WITHIN_LIMIT и REACHED_INCOME используют историю прогноза с версии Room 9.

«Финансовый след» пока исключён из используемых названий: соответствие одному из кодов не определено. Двенадцатое достижение не добавляется; переименование одного из 11 требует отдельного согласования.

### 5.2. Общие правила выдачи и XP

- Каждое достижение выдаётся один раз за всё время аккаунта. Ключ — код достижения в базе текущего пользователя; факт получения и его дата сохраняются.
- Пропуск дня, сброс серии, последующее редактирование/удаление/восстановление операции не отзывают полученное достижение и не отнимают XP.
- Новая выдача и соответствующее событие XP сохраняются атомарно. Начисление не привязывается к открытию экрана, нажатию на значок или успешному HTTP-ответу; офлайн работает тот же путь.
- Для XP используются `reason = ACHIEVEMENT`, `sourceId = reasonRef = код достижения`. Повторная обработка и повторная отправка используют уже сохранённый UUID события; повторного начисления по тому же коду нет, в том числе после будущей синхронизации с другого устройства.
- XP достижения добавляются к общему опыту из раздела 4 и сразу учитываются в уровне и титуле. Финансовых призов и ограничений финансовых функций нет.
- Награды достижений суммируются с базовыми XP и бонусами вех. Они не входят в дневной предел 55 XP за операции/отметку.
- Пример: первая операция третьего активного дня даёт +10 XP за операцию, +20 XP за веху 3 дня и +20 XP за STREAK_3, итого +50 XP за это действие. Уже выданные FIRST_CLUE, веха или STREAK_3 повторно не оплачиваются.
- При выключенных игровых элементах условия продолжают проверяться, достижения и XP сохраняются; скрывается игровое представление.

### 5.3. Первая операция, серия и возвращение

- FIRST_CLUE требует успешного первоначального создания расхода или дохода. Открытие формы, неуспешное сохранение и корректировка баланса не выполняют условие. Позднейшее удаление операции не отменяет факт её создания.
- Пять STREAK используют существующие правила активного дня, запаса и сброса из разделов 2–3. Операция или отметка без трат продвигают серию одинаково; несколько действий в одну дату дают один активный день. Первое достижение соответствующей вехи открывает значок.
- BACK_IN_ACTION требует ранее произошедшего реального сброса серии. Первая в жизни серия из трёх дней этого достижения не даёт.
- Использование дня запаса без сброса не открывает условие возвращения. После реального сброса нужны три календарных дня активности подряд; пропуск прерывает этот отдельный счётчик, даже если обычная серия сохранена запасом.
- Для проверки исторических серий и сбросов используется общий алгоритм истории. Текущее число дней само по себе не доказывает наличие прошлого сброса или уже достигнутой раньше вехи.

### 5.4. Свежие улики

- Требуются семь завершённых календарных дней подряд. В каждом есть хотя бы одна успешно созданная операция; доходы и расходы учитываются одинаково.
- У каждой операции локальная дата первоначального ввода должна совпадать с локальной датой совершения. Эти факты фиксируются при создании в часовом поясе устройства и не пересчитываются при последующей смене зоны.
- Проверяются все операции, включая шестую и последующие, которым не начислены базовые XP. Одна внесённая старая покупка делает день неподходящим и прерывает счётчик своевременности.
- День без операций прерывает этот счётчик, в том числе при явной отметке «Сегодня трат не было». Такая отметка сохраняет обычную серию по разделу 3. День запаса для FRESH_CLUES не применяется.
- Награда выдаётся после завершения седьмого дня: в течение него ещё может быть внесена операция за прошлую дату. Если приложение закрыто, завершённый период проверяется при следующем запуске без зависимости от посещения экрана достижений.
- Редактирование даты операции и её удаление не исправляют первоначальный факт своевременности. Удаление старой покупки из неподходящего дня не превращает его в подходящий. Уже выданная награда не отзывается.

### 5.5. Зависимость от даты дохода и прогноза

- FORECASTER выдаётся при сохранении будущей даты дохода из онбординга или настроек. Запись настройки, значка и события +20 XP атомарна. Открытие прежней настройки, пропуск, отмена и синхронизация не начисляют XP. Повторное сохранение и выключение игровых элементов не отзывают и не дублируют награду.
- WITHIN_LIMIT требует семи завершённых дней подряд с известными расходами и дневными ориентирами, сохранёнными до начала расходов соответствующего дня. Каждый день расходы должны быть не выше его собственного ориентира. Нулевые расходы подтверждаются отметкой; отсутствие записей не означает ноль. Нет сохранённого ориентира или данных о дне — нет основания для выдачи.
- Новый расчёт прогноза не переоценивает прошедшие дни. Для WITHIN_LIMIT нужны исторические ориентиры и данные той же валюты по правилам прогноза из 03, а не текущая сумма из макета.
- REACHED_INCOME проверяется по окончании заранее заданного периода до сохранённой даты дохода. Доступный остаток за весь период ни разу не должен становиться отрицательным; ноль допустим. Один положительный текущий остаток в последний день не подтверждает условие — требуется история изменений.
- Первый доступный ориентир фиксируется до расхода вместе с валютой, составом счетов и границами локального дня. При проверке берутся действующие расходы за эти границы, включая поздний ввод, изменения и отмену удаления. Семь дней должны относиться к одной валюте. Уже выданный значок сохраняется.
- Для периода записываются начальный остаток и дальнейшие изменения. При смене правила дохода или набора счетов новый период начинается с нового остатка. Смена валюты отображения позволяет продолжить прежний период в исходной валюте. День поступления относится к следующему периоду.
- Записи истории синхронизируются по UUID. Миграция начинает локальный учёт с момента подключения. При следующей синхронизации клиент также получает ранее сохранённые записи других устройств.

### 5.6. Существующая история

- При первом подключении достижений для пользователя фиксируется граница начала их учёта. Это отдельный этап: исходный момент подключения XP, серия, рекорд и накопленный опыт не сбрасываются.
- По старой истории однократно открываются достоверно выполненные FIRST_CLUE, STREAK и BACK_IN_ACTION, без XP задним числом. Учитываются также завершившиеся серии и сохранённые факты создания впоследствии удалённых операций.
- Старое достижение сохраняется как полученное без XP-награды. Позднейшее повторное выполнение не должно оплачивать его как новое.
- FRESH_CLUES оценивается по новым сохранённым фактам своевременности. В старых операциях исходный часовой пояс не сохранён; пересчёт в текущей зоне не доказывает выполнение семи подходящих дней.
- Новые достижения после подключения получают XP по таблице 5.1. Повторный запуск не передвигает границу учёта и не выполняет инициализацию старой истории заново.
- При будущей серверной интеграции нужно сохранить различие между старым значком без награды и новым оплаченным достижением. Автоматическое серверное начисление при приёме старого значка не должно нарушать это правило; способ согласуется в рамках синхронизации.

### 5.7. Представление

- Экран «Достижения» показывает «Открыто N из 11» и все 11 элементов при прокрутке. Открытый элемент содержит тематическую иконку, условие и дату получения; закрытый — замок, условие и достоверный прогресс, если его можно вычислить.
- Неполученные STREAK показывают прогресс текущей серии до своей цели. BACK_IN_ACTION и FRESH_CLUES используют собственные последовательности 3 и 7 дней. Полученный значок сохраняет открытое состояние при последующем сбросе счётчика.
- Три зависимых достижения остаются закрытыми без фиктивного прогресса до реализации необходимых функций. Они входят в общее число 11.
- На главном показываются реальное превью и счётчик; нажатие открывает экран достижений. «Ещё 6 достижений» из макета не является дополнительным достижением или отдельной обязательной кнопкой.
- Получение может сопровождаться коротким сообщением. Отдельный праздничный экран не предусмотрен. Награды не выдаются повторно при повторном показе сообщения или экрана.
- При выключенной игре игровые блоки скрываются, а сохранённые значки и накопление прогресса продолжаются по 5.2.

## 6. Напоминания

Настройки → «Напоминания»:
- «Напоминать об учёте»;
- время, на макете 20:00;
- «Периодичность» — «Ежедневно»;
- пояснение о разрешении;
- «Открыть настройки» для системных настроек уведомлений.

Другие режимы периодичности в дизайне не раскрыты. Настройки применяются сразу, без отдельной кнопки сохранения.

Напоминание локальное и не требует интернета. Планировщик и разрешения нужно реализовать/проверить, наличие WorkManager в старом проекте не доказывает готовность в этом.

Правила:
- если за сегодня есть активность, обычное напоминание не показывается;
- если активности нет, предложить внести операции либо подтвердить отсутствие трат;
- при серии от 3 дней текст может предупреждать о риске пропуска;
- общее ограничение — не более одного уведомления FinDetect за день, с учётом уведомления прогноза;
- отдельный повтор в 21:00 не отправляется, если уведомление уже было показано в выбранное время;
- учитывать локальное время, тихие часы и отказ в разрешении, не обещать точный запуск фонового планировщика.

Запрашивать разрешение после понятного действия пользователя, например включения напоминаний, с объяснением. При отказе основной учёт работает, карточка настроек ведёт к системным разрешениям. Нажатие уведомления открывает главный экран после PIN при необходимости.

## 7. Данные и синхронизация

| Сущность | Слияние |
|---|---|
| ActivityDay | Ключ — локальная дата; признаки операции/отметки объединяются, первый момент ввода сохраняется |
| XpEvent | Ключ UUID, повтор идемпотентен; сервер применяет лимиты и возвращает `counted`/`amount` |
| Achievement | Ключ — код; сохраняется самая ранняя дата получения |
| Progress | Итог сервера: серия, рекорд, запас, XP, уровень, пороги и достижения |

Клиент обновляет представление сразу, не ожидая сети. После синхронизации принимает итог, пересчитанный сервером. Финансовые записи отправляются раньше связанной активности/прогресса. Подробный порядок — в 01/API.

Нельзя синхронизировать только число XP и складывать два готовых итога: это создаёт дубли. Локальный журнал сохраняет события до подтверждения.

### Реализация пунктов 4–5: 17.11.2026

- `CalculateStreakUseCase.firstReachedDates()` находит первые даты достижения заданных вех по всей истории. Метод и обычный расчёт серии используют один алгоритм с общими правилами запаса, восстановления и сброса. Будущие даты игнорируются, повторные даты не увеличивают серию.
- После сохранения операции или отметки `LocalXpRepository` в той же Room-транзакции проверяет вехи 3/7/14/30/100 и добавляет награды 20/50/100/200/500 XP. Бонусы не используют дневной лимит базовых начислений и работают при выключенных игровых элементах.
- Вехи не выше исходного `legacyBestStreak` не оплачиваются. Для остальных идентичность награды задаётся `reason = STREAK_MILESTONE`, `sourceId = reasonRef = число дней`. Повторные действия, перезапуск, сброс и повторный набор серии не создают второй бонус и не меняют UUID уже записанного события.
- Перед публикацией существующей пользовательской области `initialize()` восстанавливает ещё не выданные вехи по истории после подключения XP. Это учитывает и активность, сохранённую между реализацией базовых XP и подключением бонусов, даже если та серия уже закончилась. Первое подключение XP по-прежнему только фиксирует прежний рекорд без ретроспективной выплаты.
- В событии бонуса сохраняются первая дата достижения вехи и момент первоначальной активности этого дня. Начисление не зависит от посещения главного, профиля или экрана серии. Схема Room остаётся v6.
- `XpProgressStateHolder` предоставляет единое поведение загрузки, чтения и повтора для трёх ViewModel, используя `ObserveXpProgressUseCase`. Ошибка чтения не подменяется нулевым опытом; повтор в профиле не запускает сетевое обновление аккаунта.
- На главном в карточке профиля, в строке уровня профиля и на экране «Серия дней» показаны реальный уровень, локализованный титул, XP текущего уровня и полоса прогресса. Экран серии дополнительно показывает общий опыт и остаток до следующего уровня.
- На максимальном уровне показаны «Максимальный уровень», полная полоса и растущий общий опыт. Деления на отсутствующий следующий порог нет. Удалены прежние ресурсы с макетными «140 / 250 XP» и фиксированное заполнение полосы 56%.
- `XpProgressContent` / `XpProgressCard` используют существующие ресурсы и тему, подписи из `xp_strings.xml`, не ограничивают текст одной строкой и задают доступное описание полосы XP. Добавлены стандартные светлые/ночные превью обычного, подробного и максимального прогресса, загрузки и ошибки, а также превью при ширине 320 dp и шрифте 200%.
- Переключатель игровых элементов скрывает блоки XP на всех трёх экранах. Обычный профиль и отметка без трат сохраняются. Достижения и их награды, а также реальная серверная синхронизация остаются следующими отдельными этапами.

Выполненные проверки: синтаксический разбор 220 Kotlin-файлов без ошибок; отдельная компиляция 6 доменных файлов XP и `XpProgressStateHolder`; разбор 23 XML-файлов ресурсов значений и разрешение 109 ссылок на строки, множественные формы и иконки в 12 Kotlin-файлах главного, профиля, серии и общего блока XP; `git diff --check`. Общий алгоритм серии сохранён, поиск первых вех использует тот же проход по истории. Полная Android-сборка, генерация Room/Hilt, компиляция Compose, запуск приложения и просмотр Preview не выполнялись. Gradle не запускался, автоматические тесты не добавлялись.

### Проверка пунктов 4–5 в Android Studio

Суммы ниже относятся к базовым XP и вехам серии. После подключения достижений к ним добавляются награды из раздела 5.

1. Для новой истории с уже подключённым XP вносить по одной операции в каждый активный день. При серии 3/7/14/30/100 дней общий опыт должен составлять соответственно 50/140/310/670/1 870 XP: базовые награды за все дни плюс все достигнутые вехи. Повторная операция в день вехи может добавить базовые +10 XP в пределах лимита, но не второй бонус серии.
2. День без трат тоже продвигает серию и выдаёт положенный бонус. День запаса сам не даёт XP: для активных дат 1, 2 и 4 серия достигает трёх дней только 4-го числа. Несколько действий в одну дату дают один активный день.
3. Сбросить серию и набрать уже оплаченную веху снова: её бонус не повторяется, прежний XP сохраняется. Для старого рекорда 7 дней, зафиксированного до XP, вехи 3/7 не оплачиваются; впервые достигнутые после подключения 14 дней дают +100 XP.
4. Для истории, набранной после подключения базовых XP, открыть обновлённое приложение: ранее не выданные вехи должны появиться один раз с исходными датами, даже если текущая серия уже сброшена. Повторный запуск не меняет число событий `STREAK_MILESTONE`. История, существовавшая до первого подключения XP, не оплачивается.
5. Создать операцию/отметку, затем перейти между главным, профилем и экраном серии: уровень, титул, XP и доля заполнения совпадают и обновляются без ручного перезапуска. В состоянии 700 XP ожидаются уровень 2, «Следователь», 450/750 XP; на экране серии — ещё всего 700 XP и остаток 300 XP.
6. Проверить 0 XP, точный переход на новый уровень, переход через несколько порогов одним начислением и значения от 5 000 XP. На максимальном уровне виден общий опыт, следующего порога нет.
7. Проверить загрузку, ошибку и повтор чтения XP без показа нулевого уровня. В профиле ошибка сети при обновлении аккаунта не мешает чтению локального XP. Проверить офлайн, перезапуск и изоляцию пользователей.
8. Выключить игровые элементы: блоки XP скрыты на всех трёх экранах. Создать новую активность и включить игру обратно: базовые начисления и бонусы сохранены. Проверить переносы на ширинах 320/360 dp, шрифт 200%, TalkBack и светлое/ночное превью. Отдельную тёмную палитру проверять после реализации настройки темы; текущий `FinDetectTheme` использует существующую светлую палитру и в night mode.

## Use cases

### UC-24. «Сегодня трат не было»

1. Открыть главный экран: кнопка находится под карточкой «Потрачено сегодня».
2. Если сегодня ещё нет отметки и нет сегодняшнего расхода, нажать кнопку.
3. Сохранить отметку локально, обновить серию, начислить +5 XP с дневным ограничением.
4. Показать состояние «Отмечено» до следующих суток.

Позднейшие расходы разрешены и участвуют в прогнозе, серия не теряется. Подтверждение задним числом недоступно. При выключенной игре нужен отдельный доступ к действию (см. раздел 8). Онлайн/офлайн одинаково.

### UC-25. Серия и прогресс

1. На главном показать реальную неделю, число дней и рекорд.
2. Нажать блок → «Серия дней».
3. Показать рекорд, титул, уровень и прогресс XP.
4. Сообщение о запасе появляется при его использовании/восстановлении, а не постоянно.
5. После сброса предложить начать новую без потери XP.

Состояние доступно локально; после синхронизации принимается согласованный итог.

### UC-28. Достижения

1. Нажать блок достижений на главном.
2. Показать счётчик и все доступные 11 элементов.
3. Полученные отображаются тематическими иконками, закрытые — замками с условиями.
4. Новая выдача после подключения достижений создаёт устойчивую запись и событие XP; при первичной обработке старой истории значки открываются без выплаты по правилам 5.6. Повторная синхронизация не выдаёт награду снова.

Офлайн доступны локальные условия. Достижения, требующие достоверного прогноза, не выдаются на основании моковых значений.

### UC-29. Напоминания

1. Настройки → «Напоминания».
2. Включить, выбрать время, оставить поддерживаемую ежедневную периодичность.
3. При необходимости запросить системное разрешение; при отказе показать пояснение и «Открыть настройки».
4. В подходящее время без активности показать одно напоминание с учётом дневного ограничения.
5. Нажатие открывает главный; PIN проверяется, если включён.

Интернет не нужен. При выключении напоминаний запланированные уведомления отменяются.

## 10. Отложенные возможности

### Расследование недели — UC-27

Короткий отчёт за прошлую неделю: самая затратная категория/день/покупка, мелкие повторяющиеся траты и сравнение с предыдущей неделей. Возможный мини-вызов и награда. Для текущего объёма не включены:
- блок расследования;
- сущность Investigation;
- награды/XP за расследование;
- уведомления об итогах и дополнительные достижения.

При возвращении фичи отдельно обновить дизайн, контракт и число достижений.

### Виджет

Варианты на будущее: серия либо быстрое добавление операции. Возможная реализация через Glance читает локальные данные; быстрый ввод проходит через PIN при включённой блокировке. В текущие макеты и API не включён.
