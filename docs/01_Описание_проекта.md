# FinDetect — описание проекта
Внутренний документ команды. Актуализация: 10.11.2026.

Комплект: 01 — описание проекта; 02 — базовые use cases; 03 — ИИ-прогноз; 04 — геймификация. Визуальные параметры и компоненты — в DESIGN.md, серверные поля и методы — в openapi.yaml.

## 1. Назначение и состояние проекта

Android-приложение на Kotlin и Jetpack Compose для личного учёта финансов. Пользователь вручную создаёт счета, записывает расходы и доходы, смотрит аналитику и получает подсказки по своим записям. Банковской интеграции и автоматического импорта операций в текущем объёме нет.

Приложение помогает регулярно вести учёт и планировать повседневные расходы до следующего дохода. Для этого предусмотрены серия дней, XP, уровни, достижения и прогноз.

Текущее состояние со слов команды: частично готов UI с навигацией и демонстрационными данными. Ни наличие экрана, ни описанный ниже сценарий не означают, что сохранение, сервер, синхронизация или расчёты уже реализованы. Этот комплект задаёт целевое поведение. Сведения о готовых репозиториях, тестах и базе старого учебного приложения не являются описанием готовности FinDetect.

Основа актуализации: приложенные секции дизайна 01–09, UI-kit и действующее описание дизайна. Из него сохраняются уточнения команды, например замена логотипа в шапке главного экрана названием экрана. Неотрисованные действия отдельно отмечены в разделе 9.

Платформа: Android, портретная компоновка. Валюты: RUB, USD, EUR, CNY, без конвертации. Языки: русский и английский. В макетах показана светлая тема; тёмная и системная остаются целевыми вариантами настроек, их палитра требует отдельной проверки.

## 2. Данные и правила

### 2.1 Сущности

| Сущность | Данные и назначение |
|---|---|
| Пользователь | Идентификатор, имя, почта; данные принадлежат авторизованному аккаунту |
| Счёт | UUID, название, `iconId`, валюта, начальный баланс, `includeInForecast`, даты создания и изменения, признак удаления; локальный статус синхронизации |
| Статья / категория | UUID, стабильный ключ, названия RU/EN, `iconId`, признак дохода/расхода, признак архивирования; серверный справочник, без пользовательского CRUD |
| Операция | UUID, счёт, статья, положительная сумма, дата/время совершения, необязательный комментарий, момент ввода, даты изменения и удаления; локальный статус синхронизации |
| Корректировка баланса | UUID, счёт, разница со знаком, момент корректировки и данные синхронизации |
| Активный день, XP, достижение | История активности и прогресса, подробнее в 04 |
| Дата дохода, прогноз, совет и оценка | Настройка расчёта, результат и обратная связь, подробнее в 03 |

Счета и статьи используют только векторные иконки из согласованного SVG-набора. В API и локальных данных хранится стабильный строковый `iconId`, например `wallet`, `cash`, `basket`, `coffee`. Сами SVG-файлы находятся в ресурсах клиента; для Android могут быть импортированы в Vector Drawable. API не передаёт разметку SVG или путь к Android-ресурсу. Для нового счёта клиент предлагает `wallet`. Неизвестный клиенту ключ отображается резервной иконкой `wallet`; исходный ключ не перезаписывается при чтении.

Визуальные подписи счетов вроде «Рублёвый счёт», «Кошелёк», «На будущее» в макетах не задают отдельное редактируемое описание: такого поля в форме и API нет. Реализация может показывать название иконки или валюту. Если нужна произвольная подпись, её модель следует согласовать отдельно.

### 2.2 Деньги, операции и баланс

- Сумма операции строго больше нуля, до 9 цифр в целой части и до 2 дробных. В русской форме допустимы запятая и точка; в API деньги — десятичные строки с точкой.
- Для операции нужны сумма, действующий счёт и статья нужного типа. Тип определяется статьёй, отдельного серверного поля типа нет.
- Комментарий необязателен. В общем списке основная строка — категория, подпись — комментарий, если он заполнен. В деталях категории основная строка может показывать комментарий, при его отсутствии — название категории.
- В форме операции показано поле «Дата», отдельного выбора времени в актуальном макете нет. Техническое время хранится для сортировки и API; редактирование сохраняет исходное время, новый ввод получает текущее локальное время выбранной даты.
- Начальный и фактический вводимый баланс неотрицательны. Расходы могут привести вычисляемый баланс к отрицательному значению.
- Баланс = начальный баланс + доходы − расходы + корректировки. Правка/удаление операции пересчитывает его.
- Первоначальный баланс задаётся при создании счёта. Для исправления текущего остатка используется отдельная шторка «Баланс счёта»: корректировка = фактический баланс − вычисленный баланс. Простое открытие формы её не создаёт.
- Переписывать исходный баланс вместо корректировки нельзя. В макете редактирования осталось поле «Начальный баланс»; для существующего счёта оно показывает исходное значение, а изменение текущего остатка ведёт в «Баланс счёта».
- Валюта счёта меняется только до появления операций и корректировок. Иначе API возвращает `CURRENCY_LOCKED`.

### 2.3 Валюта и удаление

Основные экраны, итоги, аналитика и прогноз показывают только выбранную валюту. Суммы разных валют не складываются. Выбор счёта в форме операции показывает все действующие счета с валютами: валюта операции определяется счётом.

Если сохранена операция другого счёта/валюты, запись остаётся сохранённой; шторка «Операция сохранена» предлагает «Переключить на EUR» либо «Понятно». Это не ошибка сохранения. Новый счёт другой валюты становится видимым после автоматического переключения валюты отображения.

Удаление мягкое. Удалённый счёт исчезает из списка, общего баланса и прогноза; новые операции на нём запрещены. Его операции остаются в истории и аналитике в исходной валюте. В контексте, где показано имя такого счёта, добавляется «(удалён)». Историческую операцию можно отредактировать, в том числе перенести на действующий счёт.

Кнопка «Отменить» после удаления — прежнее требование, отдельный макет не показан. Пока доступна отмена, серверный DELETE откладывается: уже отправленное удаление API не восстанавливает.

### 2.4 Настройки

На устройстве: валюта отображения, тема, язык, напоминания, игровые элементы, отображение советов, состояние первого запуска. Дата следующего дохода и правило повторения нужны также серверу. PIN и токены хранятся в защищённом хранилище; PIN на сервер не передаётся. Период списков хранится в памяти.

## 3. Экраны и навигация

### 3.1 Главные вкладки

Порядок: **Главный → Расходы → Доходы → Счета**. Стартовая вкладка — «Главный». «Профиль» открывается из карточки на главном и не является вкладкой. Нижняя навигация скрыта на вторичных экранах.

Справа в шапке главных вкладок — аналитика и настройки. Индикатор серии из шапки убран. На вторичных экранах — название и стрелка назад, без иконок справа. Параметры шапки и уточнение о логотипе — в DESIGN.md.

### 3.2 Главный

Сверху вниз:
1. Краткий профиль: имя, уровень, титул, XP и прогресс; переход в «Профиль».
2. Серия: число активных дней, 7 отметок недели, рекорд; переход в «Серия дней».
3. «Потрачено сегодня»: сумма расходов выбранной валюты и сравнение со вчера.
4. «Финансовый совет»: заголовок, объяснение, счётчик и шевроны для 2–3 советов; открытие «ИИ-прогноза» по карточке — принятый маршрут, отдельная кнопка в макете не нарисована.
5. Превью достижения и счётчик «N из 11»; переход в «Достижения».
6. Последние 2–3 операции; эти строки по описанию дизайна не кликабельны.
7. Плавающая кнопка «+ Добавить операцию».

Под плавающей кнопкой предусмотрен запас прокрутки, чтобы она не перекрывала последние строки. Для общего ввода шторка содержит переключатель «Расходы | Доходы», по умолчанию расходы.

### 3.3 Расходы и доходы

Чип периода, крупный итог, кольцевая диаграмма с легендой, контекстная подсказка/сравнение, список по датам и нижняя кнопка добавления. Диаграмма есть на обоих экранах в приложенных макетах. Сумма дохода в строке зелёная со знаком «+», расхода — navy со знаком «−».

На «Расходах» открывается «Добавить расход», на «Доходах» — «Добавить доход», без переключателя типа. Нажатие операции открывает редактирование; тип существующей операции не меняется.

Период по умолчанию — текущий календарный месяц целиком; на будущие даты реальные операции не создаются автоматически. Диапазон общий для расходов и доходов. На «Счетах» и «Главном» чипа периода нет: баланс текущий, блок «сегодня» за сегодня.

### 3.4 Операции

Порядок в шторке: заголовок или переключатель типа, крупная сумма, «Категория», «Счёт», «Дата», «Комментарий», «Сохранить».

Категория: отдельная шторка со строками с иконками и одиночным выбором. Счёт: пояснение о валюте, счета с иконками, остатками и валютами, выбранное значение и кнопка «Готово». Вложенный выбор возвращает в форму, не теряя введённые поля.

При переключении расхода/дохода с главного выбирается категория нового типа, несовместимая старая категория сбрасывается. Счёт, дата и комментарий сохраняются.

### 3.5 Счета

«Общий баланс», текущая сумма, список счетов и вторичная кнопка «+ Добавить счёт».

Шторки:
- «Новый счёт»: название, валюта, начальный баланс, «Значок», «Учитывать в прогнозе», «Сохранить».
- «Изменить счёт»: те же данные и «Удалить счёт». Текущий баланс меняется отдельной корректировкой.
- «Баланс счёта»: текущий остаток, поле «Фактический баланс», «Подтвердить».
- «Значок счёта»: сетка SVG-иконок в 4 колонки, выделение выбранной, кнопка «Выбрать». Выбор применяется к черновику; на счёт — после сохранения формы.
- Подтверждение удаления: «Удалить счёт „Наличные“?», «Операции останутся в истории», «Удалить» / «Отмена».

Нажатие счёта открывает редактирование. Переход к корректировке из формы счёта — требуемое действие; конкретный триггер нужно отразить в макете.

### 3.6 Аналитика и период

Основной макет аналитики: период, «Все счета», итог расходов, составные столбцы «Траты по дням», легенда и категории с суммами. По категории открывается детализация: итог, доля всех расходов и операции категории.

Гранулярность столбцов зависит от длины периода: дни, затем недели или месяцы. Диаграмма на основных вкладках остаётся кольцевой.

Период выбирается календарём: стрелки месяца, нажатие названия для полного месяца либо выбор начала/конца, «Применить». «Свой период» содержит два поля дат. Скользящие пресеты из старого документа не входят в актуальный макет.

Дополнительные фильтры «Тип / Статьи / Счёт», режим «Всё» и отдельная шторка «Детализация» в новых макетах не показаны; автоматически переносить старый интерфейс нельзя. Вход с «Доходов» и режим аналитики доходов требуют уточнения, подробнее в разделе 9.

### 3.7 Прогноз, серия и достижения

- «Серия дней»: серия и неделя, рекорд, титул/XP, пояснение, «Сегодня трат не было».
- «Достижения»: «Открыто N из 11», открытые и закрытые строки. Сводная строка «Ещё 6 достижений» в макете обозначает оставшиеся элементы, а не двенадцатое достижение.
- «ИИ-прогноз»: текстовый статус, дни до дохода, рекомендуемый ориентир на день, советы с кнопкой «Совет полезен», «Как рассчитан прогноз».
- «Как это работает»: история последних 4 недель, выбранные счета и их сумма, следующий доход, пояснение о качестве данных, «Настроить счета» → «Счета».

Подробности и вычисления — в 03 и 04. Эти разделы больше не находятся в профиле.

### 3.8 Вход, профиль, настройки

Вход: почта, пароль, «Войти», «Забыли пароль?», «Зарегистрироваться».
Регистрация: имя, почта, пароль и подтверждение пароля. Затем «Когда следующий доход?» с датой и повторением, возможностью пропустить, затем создание 4-значного PIN и главный экран.

Профиль: аватар-иконка, имя, почта, поля имени и почты, «Сменить пароль», «Уровень», «Выйти из аккаунта», «Удалить аккаунт». Смена/сохранение личных данных требует согласования API, а не имитации сохранения в UI.

Настройки: «Оформление и язык», «Валюта», «Безопасность», «Напоминания», «Игровые элементы». Подэкраны показаны для оформления, валюты и напоминаний. Настройки применяются сразу. Редактирование даты дохода и управление советами сохраняются как требования, но точки входа в новых настройках не показаны.

## 4. Хранение и синхронизация — целевая архитектура

- Источник UI — локальная база Room. Создание и изменение доступны офлайн после первого входа и загрузки справочника.
- UUID создаёт клиент. Локальные состояния: SYNCED, PENDING_CREATE, PENDING_UPDATE, PENDING_DELETE.
- Первый вход/регистрация требуют сети. Без кеша показывается ошибка с повтором; с кешем — сохранённые данные и баннер «Нет интернета. Данные сохранены на устройстве».
- Триггеры синхронизации: восстановление сети, запуск при доступной сети, сохранение, ручное обновление, периодическая задача примерно раз в 2 часа. Системное фоновое расписание не обещает точного времени.
- Одновременно один прогон. Зависимые записи не отправляются раньше родителя.
- Порядок по API: статьи → настройки даты дохода → счета → операции/корректировки → активность/XP/достижения → итоговый прогресс → прогноз и оценки советов.
- В блоке сначала отправка локальных изменений, затем получение дельты. `updatedAfter` — серверный курсор времени; сохраняется только после последней страницы. Для журнала XP применяется `createdAfter`.
- Конфликт определяется клиентским `modifiedAt`; сервер возвращает победившую версию. `updatedAt` нужен для дельты, а не для выбора победителя. Удаление не откатывается.
- Неотправленные изменения не теряются при ошибке сети. Идемпотентные PUT/DELETE безопасно повторяются, правила refresh-токена — в API.

Офлайн доступны списки, аналитика, операции, счета, локальные настройки, серия/прогресс и упрощённый прогноз. Новый серверный прогноз и новые тексты советов требуют сети.

## 5. Авторизация и защита

Регистрация/вход по почте и паролю, access/refresh-токены в защищённом хранилище. При отказе обновления сессии требуется вход, данные до явного выхода не теряются.

PIN — локальная блокировка приложения; при создании требуется повтор, при смене/отключении — проверка действующего PIN. Целевое требование: блокировка при возврате из фона после 30 секунд. В макете показано создание PIN, остальные состояния требуют той же визуальной основы.

Выход расположен в профиле. При неотправленных изменениях нужно предупредить и дать отменить выход или синхронизировать. Явный выход очищает сессию и данные текущего пользователя. Удаление аккаунта требует отдельного подтверждения и успешного серверного ответа; при сетевой ошибке удаление не имитируется.

## 6. Состояния и стиль реализации

Для данных: загрузка, содержимое, пусто, ошибка. Пустые расходы: «0 ₽», иконка чека, «Пока нет расходов», пояснение и доступная кнопка добавления. При сохранённых данных ошибка обновления не заменяет содержимое.

Форма сохраняет введённое при ошибке, блокирует повторное сохранение и обязательно снимает блокировку после завершения запроса. Макет уведомления о другой валюте показывается только после успешной записи.

Ресурсы строк, палитра, Inter и векторные иконки общие для приложения. Не переносить строки, цвета и типографику напрямую в отдельные экраны. Общие компоненты документировать KDoc и обычными light/dark Preview.

## 7. Приоритеты реализации

P0: навигация и состояния по макетам; настоящая модель данных; операции, счета, баланс; авторизация и синхронизация; аналитика и период; дата дохода и локальный прогноз; серия и отметка дня без трат.

P1: серверный прогноз и тексты советов, XP/уровни/достижения, напоминания и оценка советов, завершение профильных сценариев.

P2: более точная сезонная модель, расширенная аналитика и дополнительные визуальные темы. Ежемесячное повторение даты уже показано в актуальном дизайне и не считается отложенным.

## 8. За пределами текущего объёма

Расследование недели, виджет, банковские интеграции, конвертация валют, пользовательское создание категорий, биометрия, дополнительные языки и GBP. Исторические заметки о виджете и расследовании сохранены в 04.

## 9. Вопросы и расхождения, требующие решения команды

| Вопрос | Что зафиксировано сейчас |
|---|---|
| Аналитика с вкладки «Доходы» | В макетах подробная аналитика только расходов. Режим доходов и его подписи/переходы не считать подтверждёнными |
| Корректировка текущего баланса | Отдельная шторка есть, точный триггер из формы счёта надо дорисовать; начальный баланс не заменяет корректировку |
| Восстановление и смена пароля | Действия есть в дизайне, соответствующих методов в текущем API нет |
| Изменение имени/почты | Поля профиля есть, но нет способа сохранения в макете и метода изменения профиля в API |
| Повтор дохода | «Каждый месяц» включён в модель API; другие варианты повторения в макете не раскрыты |
| Дата дохода / советы в настройках | Нужны маршруты повторного изменения; отдельные строки в новых макетах не показаны |
| «Финансовый след» в достижениях | В старом наборе/API нет такого названия; соответствие одному из 11 кодов и условие не определены, см. 04 |
| Напоминания: периодичность | В макете только «Ежедневно», набор других режимов пока не задан |
| Уведомление риска / отмена удаления | Прежние требования сохранены, отдельные новые макеты не показаны |
| Тёмная тема | Выбор предусмотрен требованиями, приложенная палитра показывает светлую тему |

Эти вопросы не означают, что остальной функционал реализован; это границы текущей спецификации.
