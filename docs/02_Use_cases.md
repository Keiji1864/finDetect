# FinDetect — use cases базового функционала
Внутренний документ команды. Актуализация: 10.11.2026.

Целевые сценарии по актуальному дизайну. Текущий UI частично работает на демонстрационных данных; сценарии ниже не являются отчётом о готовой реализации.
Данные и ограничения — в 01, визуальные параметры — в DESIGN.md, серверный контракт — в openapi.yaml. Номера прежних UC сохранены.

ИИ-прогноз: UC-23, UC-26, UC-26A, UC-26B — в 03.
Геймификация: UC-24, UC-25, UC-28, UC-29 — в 04.
UC-27 — отложенное расследование недели.

## UC-01. Запуск приложения

1. Применить локальные тему и язык, проверить сессию.
2. Без сессии открыть «Вход». При действующей локальной сессии и включённом PIN показать блокировку.
3. После регистрации пройти «Когда следующий доход?» → создание PIN → «Главный». Пропуск даты переводит к PIN и не должен заново открывать онбординг при каждом запуске.
4. На основном экране доступны вкладки «Главный», «Расходы», «Доходы», «Счета». Стартовая — «Главный».
5. При сети запустить синхронизацию; без сети показать кеш. Если кеша нет, сообщить, что для входа/первой загрузки нужен интернет.
6. Новый запуск сбрасывает период расходов/доходов на текущий календарный месяц.

## UC-01A. Просмотр главного экрана

1. Показать краткий профиль и прогресс XP, серию недели и рекорд, расходы сегодня со сравнением со вчера, финансовые советы, превью достижения, последние операции.
2. Карточка профиля открывает «Профиль», серия — «Серия дней», достижения — «Достижения».
3. Советы листаются шевронами или свайпом. Переход по карточке в «ИИ-прогноз» — рабочее правило навигации из описания дизайна; отдельный триггер нужно подтвердить в макете.
4. Последние операции на главном не редактируются по нажатию; редактирование доступно в расходах/доходах.
5. «+ Добавить операцию» открывает форму с переключателем типа (UC-05).
6. Аналитика и настройки открываются из шапки. Точный режим подробной аналитики при входе с доходов остаётся вопросом из 01.

Онлайн/офлайн: блоки читают локальные данные. Для обновления текстовых советов нужна сеть.

## UC-02. Расходы за период

Предусловие: авторизованная локальная сессия; отсутствие счетов не блокирует открытие экрана.

1. Показать заголовок «Расходы», чип периода и крупную сумму.
2. При наличии данных показать кольцевую диаграмму по категориям, легенду и контекстный совет.
3. Ниже — операции по дням, новые выше старых.
4. Нажатие операции открывает UC-06, «+ Добавить расход» — UC-05 с фиксированным типом.
5. Без данных: «0 ₽», «Пока нет расходов», пояснение и кнопка добавления. Не рисовать фиктивные сегменты диаграммы.

Расчёт: неудалённые расходные операции выбранной валюты за диапазон, включая историю удалённых счетов. Чтение локальное, сеть обновляет базу.

## UC-03. Доходы за период

Аналогично UC-02: заголовок «Доходы», итог, кольцевая диаграмма доходных категорий, сравнение/подсказка и список доходов. Суммы строк зелёные со знаком «+». «+ Добавить доход» открывает форму без переключателя типа.

## UC-04. Выбор периода

1. Нажать чип периода на расходах, доходах, аналитике или деталях категории.
2. Откроется шторка календаря «Выбор периода»: стрелки месяца, название месяца, дни недели, сетка.
3. Нажатие названия месяца выбирает его целиком. Можно выбрать начало/конец диапазона; вариант «Свой период» показывает поля обеих дат.
4. До применения изменяется только черновик. «Применить» закрывает выбор и пересчитывает данные; закрытие без применения сохраняет прежний диапазон.
5. Начало не позже конца. Границы входят в период; для API верхняя временная граница — начало следующего дня.
6. На расходах/доходах период общий; аналитика получает его при входе и меняет собственное состояние без неожиданного изменения вкладок.

На главном и счетах чипа периода нет. Старые скользящие пресеты «неделя/квартал/год» в этих макетах не предусмотрены. Работает офлайн.

## UC-05. Добавление операции

Точки входа:
- Главный → «+ Добавить операцию»: переключатель «Расходы | Доходы», по умолчанию расходы.
- Расходы → «+ Добавить расход»: фиксированный расход.
- Доходы → «+ Добавить доход»: фиксированный доход.

1. Показать сумму, «Категория», «Счёт», «Дата», «Комментарий», «Сохранить». В фиксированном режиме есть заголовок, в общем — переключатель.
2. Дата по умолчанию сегодня. Счёт выбирается из действующих, категория — из нужного типа. Без счёта предлагается сначала создать его; сохранять фиктивную запись нельзя.
3. Выбор категории открывает строки с векторными иконками и одиночным выбором. Выбор счёта показывает валюты, остатки и кнопку «Готово».
4. Смена типа с главного сбрасывает несовместимую категорию, сохраняя счёт, сумму, дату и комментарий.
5. Сохранять разрешено только при сумме больше нуля, выбранном счёте и категории. Комментарий необязателен. Во время сохранения повторное нажатие блокируется.
6. Успешная локальная запись получает UUID и PENDING_CREATE, фиксируется момент ввода, пересчитывается баланс. При сети выполняется отправка.
7. Форма закрывается, обновляются список, главный, балансы и прогноз. Новое создание учитывается для активности/XP; повтор отправки не начисляет их снова.
8. Если валюта счёта отличается от валюты отображения, показать «Операция сохранена» с объяснением и кнопками «Переключить на Y» / «Понятно». Операция уже существует независимо от выбранной кнопки.

Ошибка локального сохранения: форма остаётся с введёнными значениями, кнопка разблокируется. Ошибка сети после успешной локальной записи оставляет PENDING_CREATE и не требует создавать запись заново. Онлайн/офлайн ввод одинаков.

## UC-06. Редактирование операции

1. Нажатие строки на расходах/доходах или в деталях категории открывает «Изменить расход/доход» с заполненными полями.
2. Тип фиксирован; категорию можно заменить только категорией того же типа. Можно менять сумму, счёт, дату и комментарий.
3. Удалённый счёт исходной записи обозначен «(удалён)». Его можно сохранить для исторической записи либо выбрать действующий; новые записи на него запрещены.
4. Сохранение пересчитывает балансы затронутых счетов и аналитику. Момент первоначального ввода для активности не меняется.
5. Несинхронизированная запись остаётся PENDING_CREATE, иначе становится PENDING_UPDATE.
6. Удаление — UC-22. Кнопка удаления операции сохранена как требование, но в приложенном варианте формы не показана.

Работает офлайн. Правка не является новой операцией для XP.

## UC-07. Счета и общий баланс

1. Показать «Счета», «Общий баланс», сумму действующих счетов выбранной валюты.
2. Строка: векторная иконка по `iconId`, название, поясняющая подпись и баланс.
3. Нажатие счёта открывает UC-09; «+ Добавить счёт» — UC-08.
4. Без счетов выбранной валюты — пустое состояние и доступное создание.
5. Удалённые счета скрыты; их операции продолжают присутствовать в истории.

Баланс считается по формуле из 01. Работает по локальной базе.

## UC-08. Создание счёта

1. Нажать «+ Добавить счёт», открыть «Новый счёт».
2. Поля: название, валюта, начальный баланс (0 по умолчанию), строка «Значок», «Учитывать в прогнозе» (включено).
3. Нажатие «Значок» открывает «Значок счёта»: сетка SVG-иконок в 4 колонки. По умолчанию выбран `wallet`. Выделить иконку и нажать «Выбрать».
4. В черновик формы записывается только `iconId`, не графический файл. Закрытие выбора без подтверждения не меняет значение.
5. «Сохранить» активно при непустом названии, поддерживаемой валюте, корректном неотрицательном балансе и выбранной иконке.
6. Сохранить локально с UUID/PENDING_CREATE, затем отправить при наличии сети. Форма закрывается.
7. Если валюта новая, переключить валюту отображения, чтобы созданный счёт появился.

Счёт создаётся и используется офлайн; сервер получает его раньше операций, которые на него ссылаются.

## UC-09. Редактирование счёта

1. Нажать счёт, открыть «Изменить счёт».
2. Изменить название, SVG-иконку через «Значок счёта», `includeInForecast`. Валюту менять только без операций и корректировок.
3. Поле «Начальный баланс» показывает исходное значение. Исправление текущего остатка выполняется UC-09A, а не перезаписью этой суммы.
4. Сохранить локально; PENDING_CREATE неотправленного счёта сохраняется, иначе PENDING_UPDATE.
5. При смене валюты разрешённого пустого счёта переключить валюту отображения.
6. «Удалить счёт» открывает UC-22.

Офлайн: доступно. Запрет смены валюты применяется локально и на сервере.

## UC-09A. Корректировка баланса

1. Из редактирования счёта перейти в «Баланс счёта». Точный визуальный триггер требует дополнения макета.
2. Показать счёт, текущий вычисленный баланс и поле «Фактический баланс».
3. Ввести корректную неотрицательную сумму, нажать «Подтвердить».
4. Создать отдельную корректировку на разницу. Если разница нулевая, запись не создавать.
5. Обновить баланс и прогноз, сохранить корректировку для синхронизации. Доходом/расходом и активностью для XP она не является.

Работает офлайн. Смена иконки или названия не создаёт корректировок.

## UC-10. Просмотр аналитики

1. Открыть «Аналитика» по иконке графика; нижняя навигация скрыта, есть стрелка назад.
2. Показать период, «Все счета», общую сумму расходов выбранной валюты.
3. Ниже — составные столбцы трат по дням, легенда категорий и суммы по категориям.
4. Длинный диапазон группировать по неделям или месяцам.
5. Нажать категорию → UC-11. Пустые данные не заменять демонстрационным графиком.

Кольцевая диаграмма относится к вкладкам расходов/доходов, а не к этому подробному экрану. Отдельный подробный режим доходов и режим «Всё» не определены новым дизайном, их поведение требует решения команды.

## UC-11. Детализация категории в аналитике

1. Нажать категорию под столбчатым графиком.
2. Открыть экран с названием категории, чипом периода, её суммой, долей общих расходов и историей.
3. В строке истории показать комментарий/название операции и дату; без комментария — категорию.
4. Изменение периода пересчитывает сумму и долю.
5. Назад возвращает в аналитику с прежними условиями.

Работает офлайн, включает исторические операции удалённых счетов. Старые панели фильтров «Тип», «Статьи», «Счёт» и «Детализация» не считаются частью текущего макета.

## UC-12. Валюта отображения

Настройки → «Валюта»: RUB, USD, EUR, CNY, одиночный выбор. Изменение применяется сразу на всех основных экранах, без конвертации. Подсказка: показываются только операции и счета выбранной валюты. Работает офлайн.

## UC-13. Тема

Настройки → «Оформление и язык» → «Тема». Светлая/тёмная/системная применяются без перезапуска. В приложенном UI-kit подробно задана только светлая палитра; остальные требуют согласованных токенов.

## UC-14. Язык

Там же → «Язык»: русский/английский, сразу, без перезапуска. Меняются ресурсы, даты и формат чисел. Категории имеют `names.ru` и `names.en` в API; стабильный ключ и `iconId` от языка не зависят.

## UC-15. PIN-код

Первичная настройка после онбординга либо Настройки → «Безопасность».

1. Показать 4 точки и цифровую клавиатуру из дизайна.
2. Для создания ввести 4 цифры и повторить. При несовпадении сообщить об ошибке.
3. Сохранить в защищённом локальном хранилище, активировать сразу.
4. Для смены/отключения сначала проверить действующий PIN.

PIN не отправляется на сервер. На макете есть создание; состояния подтверждения, смены и отключения используют ту же основу и требуют экранных текстов.

## UC-16. Разблокировка

Если PIN включён, показать замок при входе в локальную сессию и после нахождения в фоне больше 30 секунд. Верный PIN возвращает к приложению, неверный очищает ввод и показывает ошибку. Работает офлайн.

Потеря защищённых ключей требует повторной авторизации, а не незаметного снятия блокировки. Восстановление локального доступа не описано текущим серверным контрактом.

## UC-17. Синхронизация

Триггеры: доступная сеть, запуск, сохранение, ручное обновление, фоновая задача примерно каждые 2 часа.

Порядок: статьи → настройки даты дохода → счета → операции/корректировки → активность/XP/достижения → прогресс → прогноз/оценки. Отправка локальных изменений предшествует чтению дельты. Конфликт определяется `modifiedAt`, серверный `updatedAt` — для курсора. Новый курсор сохраняется после последней страницы.

Один прогон одновременно; ошибка независимого блока не теряет остальную очередь. Параметры пагинации и повторов — в API.

## UC-18. Состояния и ошибки

Загрузка, содержимое, пусто, ошибка. Ошибка обновления при наличии данных показывается поверх сохранённого содержимого. Без сети и с кешем — «Нет интернета. Данные сохранены на устройстве». При 401 сначала попытка обновить токен, затем повторный вход; локальные неотправленные записи не удаляются автоматически.

## UC-19. Регистрация и вход

1. Вход: почта, пароль, «Войти», «Забыли пароль?», «Зарегистрироваться».
2. Регистрация: имя, почта, пароль, повтор пароля. Подтверждение проверяет клиент, отдельным полем API не передаётся.
3. Сохранить успешную сессию и загрузить данные. После новой регистрации — дата дохода → PIN → главный; существующий аккаунт не проходит регистрацию повторно.
4. Неверные данные показываются без сброса остальных полей.

Нужна сеть. Действие «Забыли пароль?» присутствует в дизайне, но его API пока отсутствует; не показывать ложное успешное восстановление.

## UC-20. Выход из аккаунта

Профиль → «Выйти из аккаунта». При неотправленных данных предупредить с возможностью отмены/синхронизации. После явного подтверждения очистить сессию и локальные данные пользователя, вернуться на вход. Токен отозвать на сервере, если сеть доступна.

## UC-20A. Профиль и удаление аккаунта

1. Главный → краткий профиль → «Профиль».
2. Показать аватар-иконку, имя/почту, поля, строку смены пароля, уровень, выход и удаление.
3. Для удаления спросить подтверждение, выполнить DELETE /me. Только после успеха очистить сессию и данные.
4. При сетевой ошибке аккаунт остаётся, предлагается повторить действие.

Изменение имени/почты, сохранение полей, смена пароля и переход со строки «Уровень» пока не определены полностью. В API есть чтение и удаление профиля, но нет изменения профиля/пароля; эти действия требуют дополнения спецификации.

## UC-21. Общая механика списков операций

Фильтр: выбранная валюта, тип, диапазон включительно. Секции по локальным датам, новые сверху, операции внутри — по времени. Строка: иконка категории, категория, комментарий при наличии, сумма. В макете у заголовка дня нет обязательной суммы и закрепления при прокрутке; это не добавляется как новый обязательный UI.

На расходах/доходах и в деталях категории операции редактируются. На главном последние операции — обзор без клика.

## UC-22. Удаление операции или счёта

1. Открыть редактирование, нажать удаление.
2. Подтвердить. Для счёта: «Удалить счёт „Название“?», «Операции останутся в истории».
3. Скрыть запись локально, пересчитать баланс и связанные блоки.
4. При поддержке снекбара «Отменить» отправить DELETE после окончания его окна. Отмена до отправки возвращает локальную запись.
5. Офлайн сохранить PENDING_DELETE. Удаление записи, никогда не попавшей на сервер, не должно создавать её ради последующего удаления.

История удалённого счёта сохраняется, баланс из итогов исключается. XP и активность за первоначальный ввод не отнимаются.

## UC-30. Дополнительные настройки

- «Напоминания»: включение, время, «Ежедневно», разрешение уведомлений и открытие системных настроек — UC-29.
- «Игровые элементы»: скрытие игрового представления — 04; отдельный подэкран не нарисован.

## UC-31. Ручное обновление

На списках расходов, доходов и счетов жест обновления запускает UC-17. После завершения индикатор исчезает. Без сети содержимое остаётся и показывается понятное сообщение. Это ранее заданное поведение, жест отдельно не иллюстрируется статичными макетами.
